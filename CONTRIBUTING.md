# Contributing to ExamAdda DSA

Thank you for helping improve this learning resource.

## Before Contributing

1. Search existing issues and content to avoid duplication.
2. Use the topic or problem template.
3. Write original explanations; do not copy protected problem statements.
4. Test every implementation with normal, boundary and edge cases.
5. State accurate time and auxiliary-space complexity.

## Naming Rules

- Use lowercase kebab-case for folders and Markdown files.
- Use descriptive names such as `longest-palindromic-substring`.
- Keep one authoritative explanation per problem.
- Store language implementations inside the problem folder.

## Pull Request Checklist

- [ ] Links and Markdown render correctly
- [ ] Code compiles and tests pass
- [ ] Explanation and code agree
- [ ] Complexity is included
- [ ] Sources are cited when required
- [ ] Navigation indexes are updated
