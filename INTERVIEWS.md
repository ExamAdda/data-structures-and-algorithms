# DSA Interview Preparation Guide

[Home](README.md) • [Roadmap](ROADMAP.md) • [Contributing](CONTRIBUTING.md) • [License](LICENSE)

Use this guide after you have completed the basics in the [DSA roadmap](ROADMAP.md). It focuses on revision, problem selection, communication, and mock interview readiness.

## Interview Prep Flow

1. Review the roadmap phases you already completed.
2. Revise one problem-solving pattern at a time.
3. Solve mixed questions without looking at tags.
4. Practice explaining brute-force, optimized approach, complexity, and edge cases.
5. Run timed mock interviews before company-specific practice.

## Core Revision Checklist

| Area | What to Revise | Interview Signal |
|---|---|---|
| Complexity | Big O, space trade-offs, nested loops, recursion depth | You can compare approaches quickly |
| Arrays and Strings | Two pointers, sliding window, prefix sums, hashing | You can identify common patterns from constraints |
| Linked Lists | Reversal, cycle detection, fast and slow pointers | You can manage pointers without losing nodes |
| Stacks and Queues | Monotonic stack, valid parentheses, BFS queues | You can choose the right helper structure |
| Trees and Graphs | DFS, BFS, recursion, shortest paths, topological sort | You can model relationships clearly |
| Greedy and DP | State definition, transitions, local choices | You can justify why an approach is correct |

## Mock Interview Routine

| Round | Duration | Focus |
|---|---:|---|
| Warm-up | 15 minutes | One easy problem, spoken explanation |
| Standard coding | 45 minutes | One medium problem with tests and complexity |
| Deep dive | 60 minutes | One medium or hard problem with follow-ups |
| Review | 20 minutes | Write mistakes, missed edge cases, and patterns |

## Answer Structure

Use this structure during every interview problem:

1. Clarify input size, constraints, duplicates, ordering, and edge cases.
2. State the brute-force idea and why it may be too slow.
3. Identify the pattern or data structure that improves it.
4. Code the cleanest working solution.
5. Test with normal, boundary, and edge cases.
6. Explain time and auxiliary-space complexity.

## Readiness Targets

- Solve easy problems in 10-15 minutes with explanation.
- Solve medium problems in 30-40 minutes with tests.
- Recognize the top patterns without relying on topic labels.
- Explain trade-offs before coding.
- Recover from hints by adjusting the approach calmly.
